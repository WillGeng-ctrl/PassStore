# PassStore 实际开发计划

更新日期：2026-11-05。

阶段编号表示执行顺序，不代表已确定的发布日期；未勾选任务均尚未实现。本轮交付为隐私清理、MIT 许可、README、演示截图与开发文档，并修复验证中发现的同步上传异步异常处理及侧栏 Material 背景问题。

## 当前基线

- 已有 Windows/macOS Flutter 工程，源码版本 `1.0.0+0`。
- 已有本地加密、分类搜索、回收站、密码生成、更换主密码和加密备份。
- WebDAV 已有下载后合并、条件上传、延迟同步和主密码变化处理。
- 已有核心、数据层及 Widget 测试；缺少完整的多设备真实 WebDAV、异常退出与双平台发布验证。
- 没有账号后端、支付、移动端工程、正式安装包或已运行的持续集成。

历史资料位于 `docs/superpowers/`，商业化定价、授权后端及移动端方案仅作设计背景，不覆盖当前实现事实，也不作为当前桌面工作的前置条件。

## P1：先保证本地数据可恢复

| 任务 | 主要代码 | 验收条件 |
| --- | --- | --- |
| 原子写入密码库与设置 | `lib/data/local_vault_repository.dart`、各 Store | 同目录临时文件、flush 与替换策略；模拟写入失败后原文件仍可解锁 |
| 损坏文件保留现场 | `lib/main.dart`、本地仓库 | 无效 JSON、缺字段、认证失败显示明确错误；不得静默当成新密码库覆盖 |
| 加密封装校验与演进 | `lib/core/services/vault_crypto.dart` | 校验版本、类型和长度；设计带边界的 KDF 参数记录及旧文件读取方案，保留旧版样本 |
| 备份恢复保护 | `vault_backup_service.dart`、恢复流程 | 支持明确输入备份主密码；恢复前可保留现有加密备份；错误密码、损坏文件和中途失败不覆盖现有数据 |

完成标准：上述故障场景有自动化回归测试；旧密码库、加密备份与新格式的兼容规则写入文档，实际恢复验证通过。

## P2：让同步异常可预测

| 任务 | 主要代码 | 验收条件 |
| --- | --- | --- |
| 超时、失败与重试 | WebDAV 服务、同步协调器 | 明确请求超时和错误分类；断网不丢本地修改，重试不产生重复上传循环 |
| HTTPS 与凭据边界 | 地址处理、设置页面 | 默认拒绝不安全连接；若提供本地开发例外则明确限制；日志和错误不含应用密码 |
| 条件请求回归 | 协议服务及 mock 测试 | 覆盖 412、首次创建竞争、ETag 缺失/改变、目录不存在及非预期响应 |
| 多设备合并与删除 | `lib/core/services/vault_merge.dart` | 双端编辑/删除/恢复、时钟偏移和主密码变更均有可重复步骤 |
| 锁定与同步竞态 | `lib/main.dart`、`app_shell.dart` | 同步中锁定、连续点击、保存后立即退出，不导致已锁定界面恢复解锁或丢失已保存数据 |
| 真实服务联调 | 独立测试账号与演示密码库 | 在测试服务和至少一个实际服务验证新增、双端编辑、离线恢复、删除和改主密码；记录版本 |

完成标准：mock 测试通过，并提交使用虚构条目的联调记录；真实凭据通过本地环境提供，不进入源码、截图或测试输出。

## P3：补齐桌面安全交互

| 任务 | 主要代码 | 验收条件 |
| --- | --- | --- |
| 统一活动计时 | `lib/features/app_shell.dart` | 鼠标和键盘均正确重置计时；覆盖持续输入与完全闲置 |
| 生命周期策略 | 应用生命周期与原生入口 | 明确失焦、最小化、系统锁屏、睡眠行为，分别验证 Windows/macOS |
| 密码默认遮挡 | `edit_entry_dialog.dart` | 默认遮挡，显式点击显示与复制；与密码生成及无障碍标签一致 |
| 剪贴板边界 | 复制与计时逻辑 | 不清除后来复制的新内容；锁定、页面关闭与连续复制有回归测试 |
| 键盘与显示适配 | 页面与共享弹窗 | Tab/Enter/Escape、缩放和较小窗口可用，错误不遮挡主操作 |
| macOS 备份文件选择 | `lib/main.dart` 的导入/导出路径选择 | 补齐 macOS 原生文件选择与恢复；目前导出固定到 Documents、导入直接取消，完成后以演示数据验证 |

完成标准：更新交互测试及截图，按 [测试说明](TESTING.md) 执行桌面手工清单。

## P4：形成首个可重复发布流程

- [ ] Windows/macOS CI 固定验证过的 Flutter 版本，依次安装依赖、静态分析、测试。
- [ ] 自动构建原生产物；Windows Release 整目录打包，验证 macOS `.app`。
- [ ] 在干净系统或用户目录验证首次启动、升级及数据目录权限。
- [ ] 确定签名、公证与分发方式；生成版本说明和 SHA-256 校验文件。
- [ ] 完成依赖许可核对和发布前隐私检查，不打包真实密码库或测试凭据。
- [ ] 根据实际构建结果创建首个 GitHub Release，再补充 README 下载步骤。

完成标准：另一位开发者按文档能够构建；发布包完成安装、创建、重启解锁、备份恢复与同步验证。

## 后续决策

移动端、系统凭据/生物识别、更多存储提供方，以及账号/授权/支付功能须单独立项。引入后端前明确必要性、数据边界和维护成本；先完成桌面可靠性工作。

## 每项任务的交付要求

1. 写清复现条件、受影响数据和兼容性要求。
2. 增加能暴露问题的回归测试，完成实现并运行相关检查。
3. 数据格式变更验证旧文件读取、失败回滚和备份恢复。
4. 交互或同步变更补充目标平台验证记录。
5. 更新文档和计划实际状态，再进入下一项任务。
