# PassStore 同步设计

## 目标

第一版同步要解决一个核心问题：多台设备共用同一个 WebDAV 远程 vault 文件时，不能因为某一端点了同步就覆盖另一端的数据。

同步不是“把本地文件上传到云端”，而是固定执行：

1. 读取远程 vault。
2. 尝试用当前主密码解密远程 vault。
3. 把远程 vault 和本地 vault 合并。
4. 用当前有效主密码重新加密合并结果。
5. 保存本地并上传远程。

云端只保存加密后的 vault 文件。WebDAV 服务商不能读取明文密码、分类、备注或主密码。

## 当前代码状态

当前已经有：

- 本地 vault 加密和解密。
- WebDAV 连接测试。
- WebDAV `downloadVault` 和 `uploadVault` 基础方法。
- 条目级合并服务 `VaultMerge`。
- WebDAV 账号和应用密码保存进 vault。

当前还没有：

- 真实同步入口。
- 解锁后的自动拉取。
- 本地修改后的延迟上传。
- 本地基线 vault 记录。
- 远程文件版本记录。
- 主密码变更后的跨设备同步处理。
- 同步中、失败、冲突、未配置等真实状态。

## 核心规则

同步必须先下载，再合并，再上传。

只要远程文件存在，就不能在没有检查远程内容的情况下直接上传本地文件。

如果同步失败，本地数据必须保留。失败不能导致本地 vault 被清空、回滚或锁死。

如果本地和远程都能解密并合并，合并后的结果成为新的本地 vault 和新的远程 vault。

如果无法解密远程 vault，不能上传本地文件覆盖远程文件。

## 主密码变更

A 端修改主密码后：

1. A 端先用旧主密码解开本地 vault。
2. A 端把当前 vault 用新主密码重新加密。
3. A 端执行一次同步，上传新主密码加密后的远程 vault。

B 端在同步前仍然可以用旧主密码打开本地 vault，因为它的本地文件还没有更新。

B 端点同步时：

1. B 下载远程 vault。
2. B 用当前输入的旧主密码尝试解密远程 vault。
3. 解密失败时，判断为“远程主密码可能已变更”。
4. B 不能上传本地旧 vault。
5. UI 提示用户输入新的主密码。
6. 用户输入新主密码后，B 用新主密码解密远程 vault。
7. B 把当前已打开的本地 vault 与远程 vault 合并。
8. B 用新主密码重新加密合并结果。
9. B 保存本地，并上传远程。

B 端同步完成后，以后必须使用新主密码解锁。

## 上传时机

第一版采用保守自动同步：

- 解锁成功后，如果已配置 WebDAV，自动执行一次同步检查。
- 新建、编辑、删除、恢复条目后，本地立即保存，然后延迟 3 到 5 秒自动同步。
- 新增、重命名、删除分类后，本地立即保存，然后延迟 3 到 5 秒自动同步。
- 保存 WebDAV 设置后，不自动上传，只允许用户手动同步或等待下一次本地变更触发同步。
- 修改主密码后，必须立即执行同步。
- 用户点击同步按钮时，立即执行完整同步流程。
- 程序关闭前如果存在未同步改动，可以尝试同步；如果失败，保留本地改动，下次启动后继续同步。

自动同步需要合并短时间内的多次修改，避免每输入一次都上传。

## 同步状态

主界面同步状态至少包含：

- `未配置同步`：没有 WebDAV 地址、账号或应用密码。
- `未同步`：本地有改动，还没有成功同步。
- `同步中`：正在执行下载、合并或上传。
- `已同步`：本地和远程已完成一次成功同步。
- `同步失败`：网络、WebDAV、解密、上传或权限错误。
- `需要新主密码`：远程 vault 无法用当前主密码解开，可能已被其他设备改了主密码。
- `有冲突`：同一条目同一字段在本地和远程都被修改，需要用户选择。

`已同步` 只能在真实同步成功后显示。仅配置了 WebDAV 不能显示 `已同步`。

## 数据记录

本地需要记录同步元数据：

- 最近一次成功同步时的本地 vault 基线。
- 最近一次成功同步的远程文件标识，例如 ETag 或 Last-Modified。
- 最近一次同步成功时间。
- 是否存在本地未同步改动。
- 最近一次同步错误信息。

基线用于判断本地和远程分别改了什么。没有基线时，首次同步按“本地和远程都可能有数据”处理，走合并流程。

## 远程文件

WebDAV 设置里的地址按“目录地址”处理，例如 `https://dav.jianguoyun.com/dav/`。

第一版远程 vault 文件固定保存在该目录下的 `PassStore/passstore.vault`。

应用负责创建 `PassStore` 目录和 `passstore.vault` 文件。用户不需要手动填写文件名。

如果远程文件不存在：

- 本地已有 vault：上传本地加密 vault，状态变为 `已同步`。
- 本地没有 vault：保持当前创建或导入流程，不在同步流程里创建空库。

如果远程文件存在：

- 必须先下载。
- 必须能解密后才允许合并和上传。

## 冲突处理

第一版沿用现有条目级合并方向：

- 本地新增条目和远程新增条目都保留。
- 不同条目分别修改时自动合并。
- 同一条目不同字段分别修改时自动合并。
- 同一条目同一字段都修改且值不同，进入冲突状态。
- 冲突未解决前，不上传覆盖远程。

分类冲突第一版保持简单：

- 默认分类不可删除或重命名。
- 自定义分类按更新时间取较新版本。
- 删除自定义分类时，条目移动到 `其他`。

## UI 交互

主界面需要一个明确的同步入口，建议放在顶部同步状态旁边。

同步按钮行为：

- 未配置时点击进入同步设置。
- 可同步时点击执行同步。
- 同步中显示进行状态。
- 成功后短暂显示成功，再回到状态文本。
- 失败后显示失败状态，用户可再次点击重试。
- 需要新主密码时弹出输入框，只要求输入新的主密码，不显示或保存主密码明文。

同步失败不应该弹出大量打断式窗口。常规失败显示在同步状态区域；需要用户选择的冲突或新主密码才弹窗。

## 错误处理

网络失败：

- 保留本地改动。
- 状态变为 `同步失败`。
- 下次手动或自动同步时重试。

WebDAV 401：

- 状态变为 `同步失败`。
- 提示检查坚果云账号和第三方应用密码。

远程 vault 解密失败：

- 状态变为 `需要新主密码`。
- 禁止上传本地文件。

远程文件格式无效：

- 状态变为 `同步失败`。
- 禁止覆盖远程文件。

合并冲突：

- 状态变为 `有冲突`。
- 用户解决后再上传合并结果。

## 测试重点

实现前需要补测试覆盖：

- 远程不存在时，本地 vault 上传成功。
- 远程存在且无本地改动时，下载并更新本地。
- 本地和远程修改不同条目时，自动合并并上传。
- 同一字段冲突时，不上传并返回冲突。
- A 端改主密码后，B 端旧主密码不能覆盖远程。
- B 端输入新主密码后，可以合并本地旧数据和远程新数据。
- 本地修改后只标记未同步，并通过延迟任务上传。
- WebDAV 401、网络失败、远程格式错误不会破坏本地 vault。

## 非目标

第一版不做多用户协作。

第一版不做实时推送。

第一版不做复杂历史版本浏览。

第一版不做后台常驻服务。

同步应该服务于“自己在几台设备之间安全共享密码库”，而不是变成复杂的云协作系统。
